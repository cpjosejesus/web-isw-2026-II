Dónde quedamos

La aplicación funciona. Nadie de afuera la usa.

Lo que tenemos

  • Flask con CRUD completo sobre PostgreSQL
  • docker compose up levanta todo
  • El servidor de desarrollo escuchando en :8000

Lo que falta

  • Un solo proceso atiende una petición a la vez
  • Los archivos estáticos pasan por Python
  • Sin HTTPS, sin límites, sin réplicas

Hoy no tocamos main.py casi nada. Todo lo que agregamos vive delante de la aplicación.

La pregunta de hoy

¿Por qué poner otro servidor delante del servidor?

Suena redundante. Flask ya responde HTTP. ¿Para qué agregar una pieza más?

Flask sabe

Tu lógica: qué libro mostrar, qué guardar, qué plantilla renderizar. Eso es lo único que nadie más puede hacer por vos.

Nginx sabe

Miles de conexiones lentas, archivos, TLS, compresión, reintentos, caché. Problemas idénticos en todos los sitios del mundo.

Poner nginx delante es dejar de resolver en Python problemas que no son de tu dominio.

Bloque 1 · Peldaño 1

Lo más simple que hace nginx: entregar un archivo

Navegador→ Nginx→ disco

Sin Python, sin base de datos, sin lógica. Una petición llega, nginx busca el archivo en una carpeta y lo devuelve.

Este caso ya es útil por sí solo: un sitio de HTML, CSS e imágenes no necesita nada más. Y es la base de todo lo que sigue.

Bloque 1 · Configuración

La configuración mínima, línea por línea

server {
    listen 80;                       # qué puerto atiendo
    server_name biblioteca.local;    # para qué nombre respondo

    root /var/www/biblioteca;        # dónde busco los archivos
    index index.html;                # qué devuelvo si piden "/"

    location / {
        try_files $uri $uri/ =404;   # ¿existe? sirvo. ¿no? 404
    }
}

Siete líneas. server es un sitio; location es una regla para un conjunto de URLs. Todo el resto de la clase agrega bloques dentro de esta misma forma.

Bloque 1 · El modelo mental

Una URL es una ruta de disco, hasta que deja de serlo

GET /css/estilos.css
                 │
      root /var/www/biblioteca  +  uri /css/estilos.css
                 ↓
      /var/www/biblioteca/css/estilos.css

Nginx concatena root con la URI. Si el archivo existe, lo entrega; si no, try_files decide el siguiente intento.

El error clásico: usar alias y root como si fueran sinónimos. root agrega la URI al camino; alias la reemplaza.

Bloque 1 · Por qué importa

Un proceso, diez mil conexiones

Flask en desarrollo

Un hilo atiende una petición completa. Mientras espera, no hace nada más. Cien clientes lentos = cien bloqueos.

Nginx

Un proceso maneja miles de conexiones con un bucle de eventos. Cuando una espera, atiende otra. Nadie bloquea a nadie.

Por eso el trabajo se reparte así: nginx aguanta la multitud, Flask atiende el pedido.
